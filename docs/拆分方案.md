# 拆分方案

主站繼續當播放器。影片目錄 `v/`、封面目錄 `p/` 改放到依科目分開的 GitHub Pages repo。主站 `shorts.json` 的 `src` 和 `poster` 改成那些站的絕對網址。

這份數字由 `python3 tools/split_plan.py` 從工作區直接重算。腳本只讀檔案與 git 歷史，不改媒體、不改 `shorts.json`、不改 `index.html`、不改 `sw.js`，不搬檔，也不建立 repo。

GitHub 寫明已發布的 GitHub Pages 站不得大於 1 GB，建議中的來源 repo 也以 1 GB 為目標。文件沒有寫這個 GB 是 10⁹ 還是 2³⁰。下面的「還能再放幾批」以較緊的 **1,000,000,000 bytes** 計算，並附 1 GiB（1,073,741,824 bytes）對照。單檔上限是 100 MiB；目前最大的 mp4 是 1,383,522 bytes（1.32 MiB），最大的 jpg 是 66,306 bytes（0.06 MiB）。

## 不拆站，還能再放幾批

一批的定義：git 歷史上一個 commit 新增加的 `v/` 與 `p/` 位元組。目前 5 個 commit 就是 5 批，由小到大差很多，所以同時給平均批與最大批。

- 五批平均：118,956,969 bytes（113.45 MiB）
- 最大一批：276,105,315 bytes（263.31 MiB）（最新一批）
- 以 1 GB = 1,000,000,000 bytes，這一站還剩 405,031,257 bytes（386.27 MiB）
- 用平均批去除，還能再放 **3** 批；下一整批若仍是平均大小，第 4 批會超過 1 GB。
- 用最大一批去除，還能再放 **1** 批。
- 若 1 GB 是指 1 GiB，還剩 478,773,081 bytes（456.59 MiB），平均批還能再放 4 批，最大批還能再放 1 批。
- 換算成支數：以目前平均每支大小，1 GB 內大約還能再放 323 支，1 GiB 內大約還能再放 382 支。

批的大小從大約 44 MiB 到 263 MiB，不是定額。上面的批數是用歷史平均和歷史最大各除一次，用來決定要不要在下一批之前把媒體搬出去。

## 做法

建議 **一科一個 repo**，再加現有主站 `italymanoec/law-shorts`。11 個科目的 id 前綴各對一個站，之後補片只推該科的 repo，主站只改 `shorts.json` 的網址。

主站留下 `index.html`、`shorts.json`、圖示和 README。`v/`、`p/` 改放到新 repo 的同名目錄，並從該 repo 的根目錄開 GitHub Pages。新 repo 的預估大小只算搬過去的 mp4 和 jpg，不含播放器。

一科一站時，目前最大的一科仍遠小於 1 GB。某一科之後變大，不會把其他科的配額一起吃掉。

## 要改的網址欄位

index.html 把每一筆的 src 填進 video、把 poster 填進封面，沒有另外寫死 v/ 或 p/ 的網址。

要改的是 `shorts.json` 裡每一筆的 `src` 和 `poster`，共 475 筆、950 個欄位。`?v=` 後面的快取字串留著。`pod` 已經是 Podcast 的絕對網址，不動。`id`、`subj`、`title`、`hook`、`year`、`n`、`dur`、`podt` 也不動。

| 欄位 | 現在 | 拆分後 |
|---|---|---|
| `src` | `v/civ-s01.mp4?v=22eef7179e` | `https://italymanoec.github.io/law-shorts-civ/v/civ-s01.mp4?v=22eef7179e` |
| `poster` | `p/civ-s01.jpg?v=22eef7179e` | `https://italymanoec.github.io/law-shorts-civ/p/civ-s01.jpg?v=22eef7179e` |

其餘各筆同一規則：路徑維持 `v/<id>.mp4` 或 `p/<id>.jpg`，只把相對路徑換成 `https://<owner>.github.io/<該科 repo>/` 開頭。播放器用這兩個字串當位址，所以 `index.html` 不用改。

工作區沒有 `sw.js`。這次不新增。

跨站的 mp4 可以由主站的 `<video>` 直接播放，封面也可以直接用跨站 jpg。兩站都是 https。

## 重跑

```
python3 tools/split_plan.py
```

輸出即這份說明。媒體或 `shorts.json` 有增減時重跑即可，不必改腳本。
